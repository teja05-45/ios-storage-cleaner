## 2. Architecture audit

Dependency flow is strictly one-way: `Features → UseCases → Services → Core`, with `AppEnvironment` as the single composition root. Verified properties:

- **Core is framework-free.** All 18 Core files import Foundation (+CoreGraphics for geometry). No Photos/Contacts/AVFoundation in Core — enforced now by the import allow-list in `scripts/dependency_audit.py`.
- **Protocol-first services.** Every service has a protocol; the test target builds fakes (`ReclaimTests/SafetyTests/Fakes.swift`) instead of touching PhotoKit. This is what makes 144 tests runnable without entitlements.
- **Single source of selection truth.** `ReviewStore` is the only owner of selection state; category screens mutate through its methods; Review aggregates from it (`currentSelection`). Counts cannot drift between screens by construction.
- **Single destructive entry point.** `PerformCleanupUseCase.execute(_:confirmed:)` is the only method in the codebase that can initiate deletion (see §9).

No architectural violations found.

## 3. Swift code audit

- Zero `try!`/`as!`/force unwraps in app code (grep-verified, re-run this audit).
- Zero `print(`/`NSLog`/`fatalError` in app code; logging goes exclusively through the PII-safe `Log` wrapper (§8 of docs/26).

## 7. Bug found and fixed: BUG-01 (zero-byte group members)

**Bug:** exact-duplicate and similar-photo group members carried the enumeration-time `byteSize: 0` placeholder. `DuplicateDetector` resolved real sizes into a bucketing local and `SimilarityDetector` into scoring signals — then built groups from the *original* assets, discarding the sizes. User-visible effect: the Dashboard "could be recovered" figure, every photo-group row's bytes, and the Review totals under-reported exact-duplicates and similar-photos as 0 bytes. Screenshots and videos were unaffected (their sizes were folded back at scan time).

**Fix:** both detectors now fold resolved sizes back into group members via the existing `PhotoAsset.withByteSize(_:)` (`resolvedSizes` map in `DuplicateDetector`, `sizesByID` in `SimilarityDetector.processBucket`).

**Regression tests:** `DetectionPipelineTests.test_exactDuplicateGroup_membersCarryRealByteSizes_notZero` and `.test_similarGroup_membersCarryRealByteSizes_notZero` — each asserts member sizes and (for exact duplicates) `group.recoverableBytes` equal the scripted real sizes.

Full record: `docs/27-bug-audit.md`.

## 8. Permissions audit (automated portion)

The app's permission abstraction (`PermissionState`, `isUsable`) and every gate that reads it are fully covered by `PermissionStateTests`:

- Truth table: `.authorized`/`.limited` usable; `.notDetermined`/`.denied`/`.restricted` unusable. `.limited` is first-class, never collapsed into a boolean (ADR-04).
- Photo scan: unusable states throw `.permissionNotGranted(.photos)` **before any enumeration** (asserted by scripting assets that must never be read); `.limited` proceeds and is reported honestly via `scannedWithLimitedAccess`.
- Contact scan: same gating for `.contacts`.
- Cleanup re-gating: permission revoked between scan and confirm → every PhotoKit/contact item fails with `.permissionRevoked`, **zero** delete calls made.

**Not automatable here (disclosed):** the system permission dialogs themselves, the live `PHAuthorizationStatus`/`CNAuthorizationStatus` → `PermissionState` mapping (requires the real frameworks), and the limited-library picker with a real partial selection. See docs/25 rows "Permissions".

## 9. Cleanup safety audit (destructive call sites)

Deletion call-site sweep (grep re-run this audit): exactly **two** destructive call sites exist.

| Deletion Call Site | Feature | Caller | Confirmation Required? | Review Required? | Safe? |
| --- | --- | --- | --- | --- | --- |
| `PhotoLibraryServiceLive.deleteAssets` (`PHAssetChangeRequest.deleteAssets`) | photos/screenshots/videos deletion | `CleanupService.execute` ← `PerformCleanupUseCase.execute(_:confirmed:)` ← `ReviewViewModel.confirmCleanup()` (single button, behind `confirmationDialog`) | Yes — in-app "Delete Forever" dialog **plus** native OS "Delete N Photos" dialog | Yes — Review screen lists every item with per-item remove | **Yes** |
| `ContactServiceLive.deleteContacts` (`CNSaveRequest.delete` + `store.execute`) | duplicate-contact deletion | same single path | Yes — in-app dialog (no OS equivalent exists for contacts) | Yes — Review screen + per-field would-be-lost diff preview in the group detail | **Yes** |

Guards verified in code and by the 12 SafetyTests: no confirmation → throws; empty selection → throws; authorization re-checked at execute time; every ID revalidated against the live library immediately before deletion (stale IDs dropped and reported, never silently executed against); summary built from what the OS **confirmed**, with `bytesFreed` from an independent before/after capacity delta. Flow is always `Scan → Review → Selection → Explicit Confirmation → Revalidate → Cleanup`; no `Scan → Delete` path exists.

## 10. Performance audit (deterministic portion)

- New CI tripwires (`DetectionPipelineTests`): dHash encoding of 2,000 fixed grids; clustering of 2,000 hashes in 100 provably-separated families (exact-count assertion: 100 clusters — catches threshold/grouping regressions, not just time); contact normalization + name similarity over 2,000 synthetic contacts. Ceilings are generous (10 s) and fire only on algorithmic blowups. **These are regression tripwires, not benchmarks.**
- Memory design verified by code review: streamed SHA-256 (never full buffering), metadata-only enumeration with `autoreleasepool`, bounded TaskGroup (`min(cores, 4)`), NSCache countLimit 500, lazy thumbnails/player items, no full-resolution image loads anywhere.
- **Instruments profiling: NOT AVAILABLE IN CI** — the GitHub runner cannot produce meaningful device-thermal/memory profiles, and no real large library exists in this environment. No performance numbers are claimed anywhere in this repository.

## 11. GitHub Actions audit (workflow as extended this audit)

Two jobs, both failing correctly on error (no swallowed exit codes):

**Job `validate` (macOS 14):** checkout → toolchain inspection (`xcodebuild -version`, runtime list, first-launch preparation) → project-file OpenStep validation → **security scan** (`scripts/security_scan.py`, new) → **dependency audit** (`scripts/dependency_audit.py`, new) → `plutil -lint` → `xcodebuild -list` → Debug build → full XCTest suite (`-only-testing:ReclaimTests`) → **flakiness re-run** of the concurrency-sensitive suites (DashboardViewModel, ScanPipeline, Safety, Pruning, PermissionState) → Release build → summaries → artifacts.

**Job `ui-tests` (macOS 14, needs: validate):** the new `ReclaimUITests` bundle on the iPhone 15 / iOS 17.5 simulator — launch/dashboard contract, real-capacity rendering, permission affordances, disabled-scan safety hint.

Artifacts: raw logs **and `.xcresult` bundles** for Debug, XCTest, flakiness re-run, Release, and UI tests, uploaded `if: always()` with 14-day retention. Nothing sensitive can enter artifacts: no secrets exist (gated), no user data ever touches CI.
